# 蕾缪安：接入与维护

知识与人格固定为 0.3.0，表达参考固定为 0.3.3。已完成接入实现与原生 AstrBot 隔离联调，QQ 尚未启用蕾缪安人格。

## 文件放在哪里

| 目录 | 内容 |
| --- | --- |
| `knowledge/lemuen/` | 唯一的资料源、人格、表达参考、出处及校对说明 |
| `plugins/astrbot_plugin_lemuen/` | 小插件：调用原生检索、选择表达参考、标记说话者 |
| `scripts/lemuen.py` | `check`、`build`、`smoke` 三个维护命令 |
| `tests/fixtures/lemuen.json` | 少量事实与聊天回归用例 |
| `runtime/lemuen/build/` | 可重新生成的导入文件、人格副本和插件 ZIP |
| `runtime/lemuen/latest-smoke.*` | 最近一次实际联调结果，后续运行覆盖 |
| `runtime/research/lemuen/` | 原文缓存，用于复核出处，不进入 Git |

多轮评测报告、旧模型比较脚本、重复主题 Markdown 和生成文档不再随仓库保留。出处与人物资料没有删减。

## 运行方式

人格使用 AstrBot 原生人格管理，68 个原作块使用原生知识库管理。插件只在“已启用 + 会话在列表中 + 当前选择蕾缪安人格”同时成立时运行。

每轮从原生知识库取最多五条资料，再按既有规则选择表达参考。人际经历参考仍采用“话题词 + 召回条目”的简单规则；本次没有重新调人格。检索超时或失败时保留人格与常驻表达，跳过依赖检索的经历参考。

说话者标记跟随用户消息保存，检索资料和表达参考仅用于当前请求。群聊检索最多参考当前说话者上一次消息，避免另一位成员的话题直接接到他身上；模型仍能看到 AstrBot 提供的会话上下文。没有跨会话长期记忆或养成机制。

推荐不在该会话的原生自动知识库列表重复选择“蕾缪安”，由插件调用原生检索接口；如果 AstrBot 已注入同一知识库，插件复用已有结果。此时检索问句按 AstrBot 原生规则处理。时间线与知情字段随完整块提供，仍不是结构化的检索过滤条件。

## 检查与打包

```bash
conda activate astrbot-wsl
python scripts/lemuen.py check
python scripts/lemuen.py build
python -m unittest discover -s tests -v
```

这些命令不调用收费 API。构建产物在 `runtime/lemuen/build/`。普通 CI 同样只做离线检查、测试与打包。

原生联调显式调用 API：

```bash
python scripts/lemuen.py smoke --live
# 只检查部分场景
python scripts/lemuen.py smoke --live --cases D07,G01
```

默认通过 SSH `njuse` 创建临时 AstrBot 根目录。嵌入配置取自本地 `.env`，聊天提供商取自服务器当前启用配置；密钥不写入结果或仓库。临时实例不加载 QQ 适配器，也不启动 WebUI、systemd 服务或 NapCat。结束后删除临时数据库，保留本地最近一次合成对话结果。真实会话记录不会被读取。

## 在 njuse 启用时

以下操作尚未执行。服务与 QQ 已经正常运行，不需要重新登录。

1. 在本地运行 `python scripts/lemuen.py build`。
2. 经 SSH 隧道打开 AstrBot WebUI：<http://127.0.0.1:16185>。
3. 添加 OpenAI 兼容嵌入提供商：Base URL `https://dashscope.aliyuncs.com/compatible-mode/v1`，模型 `qwen3.7-text-embedding`，维度 1024，维度发送模式 `always`。Key 从自己的 `.env` 配置到后台，不写入人格文件。
4. 创建名为“蕾缪安”的知识库，选择该嵌入提供商。稠密和稀疏候选各 20，最终返回 5，重排序暂不配置。通过预分块 JSON 导入生成的 `astrbot-import.json`；每条资料作为完整块。
5. 创建名为“蕾缪安”的人格，填入生成的 `persona.md`。初期不配置开场共同往事、工具和技能。
6. 从本地 ZIP 安装 `astrbot_plugin_lemuen.zip`。安装默认关闭；在插件配置中填写测试私聊、测试群的精确 UMO，再启用。空列表不作用于任何会话。
7. 仅在这些会话选择“蕾缪安”人格；用新会话开始试用，避免旧人格历史影响判断。

回退时关闭插件，并把试用会话的人格改回原选择。原有 QQ 登录、模型和其他会话配置保持独立。

人物资料更新后重新检查、打包、更新对应知识库；修改表达参考需要更新插件 ZIP，修改人格需要更新原生人格。插件不在启动时自动覆盖后台内容。更换嵌入模型或维度需重建索引。

## 本次验证

2026-09-24，在 njuse 临时目录使用 AstrBot 4.27.4 和当前启用的 deepseek-v4-pro：

- 原生插件加载成功；9 份主题文档、68 个原作块完整入库。
- 6 道知识检索检查均在前五条召回参考资料。
- 主联调完成 10 轮实际回复，覆盖现实／博士身份切换、旧友分歧、道歉对象和两位群成员交替发言；群成员的信息没有混用。此前两轮轮椅设计问答也完成了实际流程验证。
- 使用原生历史保存逻辑，确认说话者标记保存、检索资料不沉积到后续历史。
- 离线测试覆盖启用范围、人格切换、重复注入、实际超时、空库、检索异常及同群说话者归属；原有初始化与迁移测试同样通过。
- 主联调检索中位耗时约 0.30 秒，整体回复中位约 19 秒，单轮约 7–45 秒。样本有限，不能保证未来延迟。
- 线上主配置校验值未变；临时实例已删除，没有向 QQ 发送消息。

最近十轮原始回复位于 `runtime/lemuen/latest-smoke.md`，后续联调覆盖这份结果，不再累计多轮报告。

接入通过不代表所有台词已理想化：仍有泛化说理、倾诉引导，以及给原作经历添细节的问题。按用户要求，本次只迁移既有表达逻辑，没有继续调整人格。

自动 CD 仍需能访问 njuse 内网的自托管 runner；本次构建和提交不等于部署。
